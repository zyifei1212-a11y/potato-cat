## 5. 第二版已确认的产品范围

第二版包含三个核心模块：

1. 专注币消费和商城。
2. 冰箱贴板。
3. 猫咪单饰品佩戴系统。

### 5.1 专注币与商城

商城商品至少分为：

- 小贴纸。
- 猫咪饰品。
- 冰箱背景板。

商城需要支持：

- 商品名称、说明、分类、主题、价格和预览图。
- 专注币余额不足提示。
- 购买确认。
- 购买成功后写入统一交易账本。
- 已拥有状态。
- 防止重复购买同一不可重复商品。
- 已拥有贴纸、饰品和背景板的收藏视图。
- 交易失败时余额与库存不能出现半完成状态。

价格尚未最终确认。之前提出过以下建议，但只能作为初始调试值：

- 普通小贴纸：2–3 币。
- 主题贴纸：4–6 币。
- 普通饰品：8–12 币。
- 节日饰品：15–20 币。
- 背景板：25–40 币。

用户尚未确认最终币价，正式内容制作前需要再次讨论。

### 5.2 冰箱贴板

需要支持：

- 将已经购买的贴纸放到冰箱板。
- 自由拖动。
- 缩放。
- 旋转。
- 调整前后层级。
- 删除摆放，但不删除商品所有权。
- 更换已拥有的背景板。
- 自动保存布局。
- 窗口缩放后贴纸位置不乱。
- 一键整理和一键清空板面。

冰箱贴板属于装饰和收集功能，不应反向修改番茄钟、待办或奖励结算逻辑。

### 5.3 猫咪饰品：最终确认规则

这是硬性产品决定：

- 无论内部有几个定位类型，每只猫同时只能佩戴一件饰品。
- 用户选择第二件时，第一件自动卸下。
- 主界面像素猫显示饰品。
- 日常真实悬浮猫显示饰品。
- 霸屏动画永远不显示饰品。
- 钻袋子彩蛋永远不显示饰品。
- 霸屏或彩蛋结束后，恢复此前佩戴的饰品。
- 第一批优先做头部和颈部饰品，眼镜和身体挂件可以后置。

日常真实悬浮猫至少包括：

- `idleLoaf`
- `focusTyping`
- `hoverLook`
- `sleepBreathing`
- `dragLift`

不应用饰品的状态：

- `breakOverlay`
- `bagEasterEgg`

### 5.4 饰品主题

节日饰品候选：

- 春节：红围巾、福字帽、醒狮帽、红色挂坠。
- 劳动节：黄色安全帽、工具包、劳动奖章。

- 圣诞节：圣诞帽、红绿围巾、鹿角、铃铛项圈。
- 可后续扩展元宵、端午、万圣节、情人节等。

职业饰品候选：

- 白领领带。
- 服务生领结或围裙。
- 厨师帽。
- 医生听诊器。
- 程序员眼镜或耳机。
- 画家贝雷帽。
- 建筑工作者安全帽。
- 教师眼镜或书本挂件。

第一批不要一次制作全部内容。先用圣诞帽和白领领带验证真实猫与像素猫的叠加机制。

### 5.5 贴纸主题

已经提出的正式主题方向：

## 6. 第二版推荐技术方案

以下是已讨论并推荐的实现方向；开始编码前应根据现有代码作最小化设计，不要机械照抄字段名。

### 6.1 商城数据建议

建议新增独立领域类型，而不是把商城字段塞进 `Todo` 或 `AppSettings`：

```ts
type ShopItemKind = "sticker" | "accessory" | "fridgeBackground";

interface ShopItem {
  id: string;
  kind: ShopItemKind;
  name: string;
  description: string;
  theme: string;
  price: number;
  previewSrc: string;
  availableFrom?: string;
  availableUntil?: string;
}
```

需要扩展奖励交易类型以支持消费，例如：

```ts
type RewardTransactionType =
  | "focus_completed"
  | "todo_completed"
  | "daily_four_bonus"
  | "purchase";
```

消费交易金额建议为负数，并继续使用唯一 `sourceKey` 防止重复扣款。

### 6.2 饰品独立图层方案

禁止为“每只猫 × 每个状态 × 每件饰品”制作完整合成图。应使用：

```text
猫咪主体图层
  + 饰品透明图层
  + 爱心、星星、感叹号等特效图层
```

每件饰品只准备：

- 一份真实风格透明 PNG/WebP。
- 一份像素风透明 PNG。
- 商品预览图和元数据。

内部仍需要定位类型，但不代表可以同时佩戴：

```ts
type AccessoryAnchorKind = "head" | "neck" | "face" | "body";
```

每只猫、每个视觉状态维护锚点：

```ts
interface AccessoryAnchor {
  x: number;
  y: number;
  scale: number;
  rotation: number;
  layer: "behind" | "front";
}
```

锚点配置负责适配不同猫咪头型和姿势；饰品素材本身不为每只猫重复制作。

### 6.3 动画跟随原则

- 如果猫咪动画是整个容器的轻微移动、呼吸或缩放，饰品放在同一动画容器中一起运动。
- 如果动作只改变前爪，头部和颈部饰品应保持稳定。
- 如果状态切换使用不同猫咪图片，每张状态图片使用对应锚点。
- 不对霸屏视频做逐帧头部跟踪。
- 不为袋子彩蛋制作饰品版本。

### 6.4 冰箱贴板数据建议

贴纸实例与贴纸商品所有权必须分开：

```ts
interface FridgeStickerInstance {
  id: string;
  stickerId: string;
  x: number;
  y: number;
  scale: number;
  rotation: number;
  zIndex: number;
}

interface FridgeBoardState {
  backgroundId: string;
  stickers: FridgeStickerInstance[];
}
```

同一张已拥有贴纸能否在板上重复摆放尚未最终确认。建议初版允许重复摆放，但每个实例有独立 `id`。

### 7.4 阶段 2.3：猫咪单饰品系统

目标：先让圣诞帽和白领领带正确出现在煤煤身上。

任务：

- 购买后立即佩戴。
- 每只猫同时只能佩戴一件。
- 像素煤煤五个状态的锚点。
- 真实煤煤日常五个状态的锚点。
- 霸屏和彩蛋隐藏饰品。
- 特殊动作结束恢复饰品。
- 悬浮窗口与主窗口同步。
- 佩戴、卸下和换装回归测试。

阶段验收：

- 饰品不明显漂浮、不遮住猫咪眼睛或键盘。
- 猫咪切换状态时饰品不会闪到错误位置。
- 霸屏和钻袋子期间完全没有饰品残留。
- 同时绝不会出现两件饰品。

### 7.5 阶段 2.4：正式内容包

目标：机制稳定后再批量生成和切图。

建议首批：

- 十二生肖 12 张贴纸。
- 圣诞、春节、中秋节饰品。
- 白领领带、服务生领结、厨师帽。
- 1–2 张冰箱背景板。

不要在商城、贴板和锚点机制尚未验收前批量制作 64 张主题贴纸。

### 7.6 阶段 2.5：第二版候选版和正式版

任务：

- 完整数据迁移测试。
- 多窗口同步测试。
- 性能、内存和安装包体积检查。
- Windows 快捷方式、图标和卸载检查。
- Alpha 安装包。
- Release Candidate 安装包。
- 用户验收后生成正式安装包。

整个第二版尽量只安装测试 2–3 个里程碑版本，不为每次前端修改生成安装包。
